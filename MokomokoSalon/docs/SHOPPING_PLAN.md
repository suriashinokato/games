# ポイントでの買い物に向けた設計メモ

## 1.6までに実装した範囲

広場の描画とお店の配置は `scripts/town_view.gd` に分離しています。
お店には安定したID（`salon`、`bakery`、`tailor`、`general_store`）があり、`main.gd` の `visit_place()` が移動先を選びます。
`general_store` は準備中の案内のみです。価格・購入・残高・持ち物はまだ実装していません。
サロンの累計得点 `total` と採点・アルバムの仕組みは維持しています。パン屋は `bakery.total`、服屋は `tailor.total` に別記録し、広場で3店舗の合計を表示しています。

## 次に買い物を実装するときの方針案

- 累計実績 `total`・`bakery.total`・`tailor.total` は減らさず、買い物用の残高 `wallet` を別に持つ。
- 採点を確定する一度だけ残高を加算し、結果の再開や広場への往復で重複付与しない。
- 商品はID・名称・価格・種類で定義し、購入した商品IDを持ち物として保存する。
- 残高確認、引き落とし、持ち物追加を一つの状態変更として処理し、同じセーブとバックアップに保存する。
- 旧セーブからの移行時に過去の累計点を残高へ引き継ぐか、更新後の接客から貯めるかは、買い物実装時に決める。
- 最初の商品は、既存の依頼や正答を変えないサロン装飾などを候補とする。髪かざりを商品にする場合は、未購入品を必須とする依頼が出ないよう依頼生成も見直す。
- 価格・初期残高・品揃えを決めた後、残高不足、購入連打、保存失敗、再開、旧データ移行を検証する。

これは今後の設計案です。1.6の累計得点表示を、使用可能な買い物残高として扱ってはいません。
