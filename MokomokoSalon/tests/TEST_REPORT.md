# 検証報告（絵本版1.2・おめかしアルバム）

実施日：2026年10月23日（日本時間）

## 結果

Godot 4.5.1 StandardでインポートとWindows x86_64 Releaseの書き出しに成功しました。
ルール・保存の1,524チェック、ソースプロジェクトとWindows実行ファイルそれぞれで48チェックが通過しています。
UIの48チェックには10枚のスクリーンショット保存の確認を含みます。
最終のインポート・ルール・UI・書き出し・Windows版UI・通常起動のログにはエラー・警告がありません。

## アルバムと互換性の検証

- 旧形式（albumフィールドなし）の受付・選択途中・採点済み結果をJSON化し、復元とディスク読み書きを確認。
- 旧セーブの進行・選択・得点を保持し、存在しない過去の衣装を作らないことを確認。
- 採点済み結果を再開しても点数・アルバムを二重加算しないことを確認。
- 125人分を進め、各衣装・得点の記録と120枚の上限、古い5枚の入れ替えを確認。
- 120枚のセーブが既存の64 KiB上限内で保存・復元できることを確認。
- 壊れた本体から、アルバムとゲーム進行を同じバックアップから復旧。
- 不正な型、範囲、得点、重複番号、上限超過のアルバムを拒否。
- 空のアルバム、1枚の両端ボタン、新しい順の表示、前後のページ送りを確認。
- 0点のおしゃれも、希望の衣装ではなく実際に選んだ衣装で表示。
- 選択途中での開閉と結果画面での閲覧が進行を変更しないことを確認。
- タイトルから保存済みアルバムを閲覧、Escで閉じる操作、背景ボタンの入力遮断を確認。
- 960×600でアルバムの閉じるボタンをクリックできることを確認。
- 「はじめから」のキャンセルで履歴を保持、確定で進行と履歴を初期化。

## 既存機能の回帰検証

- 受付→着せ替え→結果→次のお客→日付更新、36人・12日分の得点・最高点。
- 全12依頼×全48通りの採点、部分一致、不一致、未選択での完成防止。
- 二重採点、二重の次客処理、結果確定後の選択変更を防止。
- JSON検証、途中再開、バックアップ保持、保存失敗時の通知と未保存で戻る際の確認。
- 音の切り替えと保存、タイトルでの音設定、新規開始の確認。

UIテストはGodotへマウスの移動・押下・解放イベントを送り、UIの反応を検証します。
今回、UIテストの入力座標を明示的にビューポート座標として扱い、縮小時もクリック対象と一致するようにしました。
ルールテストは `tests/_runtime`、UIテストは環境変数 `MOKOMOKO_QA_DIR` で指定した `tests/_runtime/ui` と `tests/_runtime/export_ui` を使用しました。
これらのテストは通常の `salon_save.json` を使いません。
Windows実行ファイルにはテスト、検証セーブ、参照画像を含めていません。

## キャラクターアイコン差し替え後の確認

- うさぎ「もも」の原画を組み込み画像生成で制作し、PNGとICOへ変換。
- ゲーム用PNGは256×256、ブラウザー用PNGは32×32。
- Windows用ICOの16/32/48/64/128/256pxと、favicon ICOの16/32/48pxを読み込み検証。
- アイコンを反映したWindows版を再書き出し。実行ファイルから抽出したアイコンが「もも」であることを目視確認。
- 最終Windows版のUI検証は48チェック、失敗0、終了コード0。エラー・警告なし。
- ログは `tests/_runtime/icon_export.log` と `icon_ui.log`、抽出画像は `exported_icon.png`。
